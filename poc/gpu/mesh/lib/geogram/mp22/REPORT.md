# MP22: why the MP20-patched Geogram fails s4_star3_000 / _107 on Linux (investigation, not frozen, not committed)
Setup: ubuntu:24.04 arm64 container (OrbStack, native on the M1), g++ 13.3, libstdc++; same scripts as MP21a, pinned tarball, corpus hashes all match EXPECTED_SHA256*. Work under storage/mesh/mp22/.
- Reproduced (verified): patched build fails both pairs, 6 rows, same as CI.
- Mechanism (verified for both pairs by instrumented copy, `storage/mesh/mp22/inst/msi_inst.cpp`): the hypothesis was wrong in two parts.
  1. The failing component is NOT one the MP20 patch touched. It is an unpatched component whose start vertex is a free vertex; its +z ray passes exactly through the contact vertex (and lies in the plane of a facet) of another body (000: ray x=-25,y=0 from the octahedron bottom (-25,0,-3) through the tetrahedron apex (-25,0,5); 107: through (-6,0,8)). Exact orient_3d is 0 for those facets.
  2. classify() runs after intersect_epilogue() has restored SOS_ADDRESS mode (line ~795), so the double* orient_3d_SOS sorts by pointer: vertex order after mesh_colocate_vertices (std::sort tie-break, differs per standard library) and the stack addresses of the locals q1,q2 (q1<q2 on Linux, q2<q1 on M1). The patched centroid path uses ExactPoint, whose SOS is coordinate-lexicographic and platform independent.
  Result: Linux counts 1 hit on a closed tetrahedron (odd, geometrically impossible), M1 counts 0. Standalone replay `sos_replay.cpp` with only the two observed memory orders reproduces 0 vs 1; of 720 orders of the six points, 216 give 1 hit.
- MP22 patch (`geogram_mp22.patch`, on top of MP20): for unpatched components cast the ray with exact orient_3d only, skip facets by bounding box, and if any facet is hit degenerately tilt the direction (fixed offsets list), falling back to the old code only if all 8 are degenerate. Non-degenerate rays are unchanged.
- Results (touch 240 / held-out 1137 / set 3 1602 / set 4 first 200 pairs 600 rows): M1: MP20 0 FAIL, MP22 0 FAIL, outputs byte-identical on all 3579 rows. Linux container: MP20 held-out 6 FAIL, set 3 2 FAIL, set 4 6 FAIL (new: MP20 also fails on the development sets there); MP22 0 FAIL on all four.
- Caveat: set 4 is now used for diagnosis, so it is spent; MP22 needs a fresh untouched set 5. Proposed classes: star3/star3r/star3deep/path4 and vertex-contact boxes with aligned axes (ray through contact vertex), octahedra and boxes with vertical axes, ray lying in a facet plane, curved-curved, nested_vertex, twopoint/threepoint.
